----------------------------------------------------------------
PROJECT STRUCTURE
----------------------------------------------------------------
Zyhawk/
├── backend/        (Node.js + Express, port 3000)
├── frontend/       (React + Vite, served via nginx, host 80 -> container 8080)
├── landing/        (static landing page, deployed separately)
├── docker-compose.yml
├── .env.example
└── Docker_Guide.txt

----------------------------------------------------------------
TECH STACK
----------------------------------------------------------------
Backend  : Node.js, Express, Supabase (Postgres), Puppeteer/Chromium
           (PDF generation), ZeptoMail (transactional email)
Frontend : React 19, Vite, Tailwind CSS
Database : Supabase (Postgres) — hosted, prod + dev projects
Storage  : Supabase Storage buckets (avatars, PO docs, vendor docs,
           finance docs, historical data, 3D models)
Docker   : Backend + Frontend containers (Dockerfile local testing
           ke liye hai; live production Railway pe chalta hai)

----------------------------------------------------------------
LIVE DEPLOYMENT (RAILWAY) — YE ASLI PRODUCTION FLOW HAI
----------------------------------------------------------------
Git remote: https://github.com/vineetgoyal686-cmyk/ZYREX.git

Railway is repo ko GitHub se connected hai aur `backend/Dockerfile`
/ `frontend/Dockerfile` khud detect karke build+deploy karta hai —
manual `docker build`/`docker push` ki zaroorat NAHI hai.

Live update karne ke liye bas itna karna hai:

        git add <files>
        git commit -m "message"
        git push

Push hote hi Railway naya build bana ke automatically deploy kar
deta hai. Docker Desktop is machine par installed hone ki bhi
zaroorat nahi hai sirf deploy karne ke liye.

----------------------------------------------------------------
LOCAL DEVELOPMENT (BINA DOCKER KE — ROZANA KA TAREEKA)
----------------------------------------------------------------
Docker sirf packaging/consistent-deploy ke liye hai — normal coding
aur testing ke liye iski zaroorat nahi. Seedha chalao:

        cd backend
        npm run dev        (port 3000)

        cd frontend
        npm run dev        (Vite dev server)

----------------------------------------------------------------
LOCAL DOCKER TESTING (OPTIONAL — SIRF DOCKER BUILD KHUD TEST KARNA HO TOH)
----------------------------------------------------------------
Agar production jaisa poora Docker build local par test karna ho:

Step 1: Docker Desktop install karo (docker.com/products/docker-desktop)
Step 2: Terminal me Zyhawk folder me jao
Step 3: Command chalao:

        docker-compose up --build

Step 4: Browser me kholo:
        - Frontend : http://localhost
        - Backend  : http://localhost:3000

----------------------------------------------------------------
ENVIRONMENT VARIABLES (.env)
----------------------------------------------------------------
File location: backend/.env  (prod credentials)
             backend/.env.local  (local dev overrides — agar hai
             toh ye .env se priority leta hai app start hote waqt)

SUPABASE_URL=<supabase project url>
SUPABASE_SERVICE_KEY=<supabase service role key>
FRONTEND_URL=<deployed frontend url>
ZEPTOMAIL_API_KEY=<zeptomail api key>
ZEPTOMAIL_FROM_EMAIL=<sender email>
ZEPTOMAIL_FROM_NAME=<sender name>
ZEPTOMAIL_TEMPLATE_INVITE=<template id>
ZEPTOMAIL_TEMPLATE_OTP=<template id>
ZEPTOMAIL_TEMPLATE_RESET=<template id>
ZEPTOMAIL_TEMPLATE_ORDER_ACTION=<template id>
ZEPTOMAIL_TEMPLATE_ORDER_ACTION_DIRECT=<template id>
ZEPTOMAIL_TEMPLATE_ORDER_ACTION_NOREASON=<template id>
PORT=3000

Railway pe ye variables Railway project ke apne "Variables" tab me
set hote hain (backend/.env file wahan upload nahi hoti) — ye .env
file sirf local development ke liye hai.

IMPORTANT:
  - .env / .env.local dono PRIVATE hain
  - Git me nahi jaate (.gitignore me hai)
  - Docker IMAGE me nahi jaate (.dockerignore me hai)
